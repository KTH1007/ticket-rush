# 테스트 웹 페이지

백엔드 흐름(줄서기, 순번 폴링, 좌석 선택과 홀드, 결제, 조회와 취소)을 브라우저에서 직접 눌러 확인하는 페이지다. 정식 프런트가 아니고 빌드 도구 없이 바닐라 JS(ES 모듈)로 만들었다.

## 실행

nginx가 이 폴더를 `/app/`으로 서빙한다. 앱 2대와 nginx를 띄우는 compose로 실행한다.

```bash
docker compose -f docker-compose.yml -f docker-compose.app.yml up -d --build
docker exec -i tr-postgres psql -U ticketrush -d ticketrush < scripts/seed-event.sql   # 공연과 좌석 3만 석
```

브라우저에서 `http://localhost:8080/app/`을 연다. 페이지가 `/api/...`를 상대 경로로 부르므로 같은 출처이고 CORS 설정이 필요 없다. `localhost`와 `127.0.0.1`은 다른 출처이니 한 가지 주소로 열어야 한다.

파일을 고치면 새로고침만으로 반영된다(볼륨으로 연결, 재빌드 없음).

## 화면

| 구역 | 하는 일 |
|---|---|
| 1. 공연 | 공연 목록을 불러오고 선택하면 좌석 배치와 상태를 불러온다 |
| 2. 줄서기와 순번 | 줄서기 후 `nextPollIntervalMs`대로 순번을 조회한다. 순번이 0이 되면 승격된 것이다 |
| 3. 좌석 선택과 홀드 | 캔버스에서 좌석을 클릭하거나 버튼으로 선택(최대 2석), 휴대폰 번호를 넣고 홀드한다 |
| 4. 결제 | 홀드 응답의 `orderId`, `amount`로 결제한다(가짜 PG는 `paymentKey`를 검사하지 않는다) |
| 5. 조회와 취소 | 예매번호와 휴대폰 번호로 조회하고 취소한다 |

오른쪽 로그에 요청마다 시각, 요청, 상태 코드, 지연(ms), `Retry-After`, `X-Cache-Status`, 오류 코드, `X-Request-Id`가 쌓인다.

## 옵션

- 조회 간격을 따른다: 끄면 0.5초 간격으로 순번을 조회한다
- Retry-After를 지킨다: 끄면 429나 503 뒤 3초 만에 다시 요청한다
- 더 오래된 builtAt의 스냅샷은 무시한다: 끄면 앱마다 다른 스냅샷이 그대로 표시된다

## 좌석 색

등급별 색(VIP, R, S)은 선택 가능한 좌석, 주황은 홀드됨, 회색은 판매됨, 빨강은 내가 선택한 좌석, 보라는 내가 홀드한 좌석이다.

## 알아 둘 점

- 홀드 만료 시각은 서버 시간대(Asia/Seoul)로 해석한다.
- 같은 번호로 한 공연에서 잡을 수 있는 좌석은 2석까지다. 다시 시험하려면 "임의 번호"로 번호를 바꾼다.
- 홀드 뒤 다시 시작하려면 "처음부터"를 누른다.
